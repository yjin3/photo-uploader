# Photo Uploader

Tailscale로 연결된 Android → PC 사진 전송 앱. 로컬 Flutter/Android Studio 설치 불필요.

## APK 만들기

1. 이 폴더의 모든 파일(`android/gradle/wrapper/gradle-wrapper.jar` 포함)을 GitHub 저장소에 업로드합니다.
2. **Actions → Build Android APK → Run workflow**를 실행합니다.
3. 완료된 실행의 **photo-uploader-apk** Artifact를 다운로드하고 압축을 풉니다.
4. `app-arm64-v8a-release.apk`를 Android 스마트폰에 설치합니다.

Java 17과 실행 시점의 최신 stable Flutter를 사용합니다. Android 최소 API는 24 이상이며 Flutter 기본값이 더 높으면 따릅니다. APK는 개인 설치용 debug 키로 서명합니다. 검증한 Dart 의존성 버전은 저장소의 `pubspec.lock`에 고정합니다.

빌드 시간을 줄이기 위해 업로드 대상인 ARM64 APK만 생성합니다. Flutter/Pub 및 Gradle 캐시를 재사용하고 Gradle 작업 캐시와 병렬 실행을 활성화했습니다. 첫 실행이나 SDK/의존성 변경 시에는 다운로드와 초기 컴파일이 필요합니다. 같은 브랜치에 연속으로 push하면 이전 실행을 취소하고 최신 실행만 진행합니다. 전체 ABI가 필요하면 워크플로의 `--target-platform android-arm64` 옵션을 제거하세요.

## PC 서버 실행

Python 3.10 이상:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r pc_server/requirements.txt
.\.venv\Scripts\python pc_server/server.py
```

PC와 스마트폰 모두 Tailscale에 로그인하고 서로 연결되어 있어야 합니다. PC의 Tailscale IPv4 주소(`tailscale ip -4`) 또는 MagicDNS 이름을 앱 설정에 입력합니다. 예: `http://100.101.102.103:8000`. 기본 표시 주소 `100.x.y.z`는 예시이므로 실제 주소로 변경해야 합니다.

서버는 `0.0.0.0:8000`에서 수신합니다. PC 방화벽과 Tailscale 접근 규칙에서 스마트폰 → PC TCP 8000을 허용하세요. 브라우저에서 `http://PC주소:8000/health`로 연결을 확인할 수 있습니다. 공유기 포트 포워딩은 필요하지 않습니다. 서버 자체 인증은 없으므로 방화벽에서 Tailscale 대역/필요한 기기로 접근을 제한하세요.

사진은 `pc_server/uploads/20261106_153000_태그/`에 저장됩니다. 태그가 없으면 시간만 사용하고, 같은 초의 요청은 `_1` 등을 붙입니다. 경로 문자를 정리하며 같은 이름의 파일을 덮어쓰지 않습니다. 모든 파일 저장을 마친 뒤 HTTP 200을 반환합니다. 응답이 유실되어 재전송하면 별도 디렉터리가 생길 수 있습니다.

사진 파일명은 원본 이름과 확장자를 유지합니다. 원본 이름이 없거나 GUID이면 `20261106_153000_001.jpg`처럼 수신 일시와 순번을 사용합니다. 확장자가 없으면 파일 헤더 또는 이미지 MIME 유형으로 JPEG/PNG/HEIC 등의 실제 형식을 확인해 확장자를 붙입니다. 확장자만 보정하며 이미지 데이터는 변환하지 않습니다. 서버 수정은 재시작 후 적용되므로 기존 APK에서 보내는 GUID 파일명도 보정됩니다.

## 갤러리 선택 또는 카메라 촬영

**사진 선택**은 기존 갤러리에서 여러 사진을 가져오고, **카메라**는 앱 안의 연속 촬영 화면을 엽니다. 셔터를 누를 때마다 별도 확인 없이 사진을 저장하며, **완료 (N장)**를 한 번 누르면 목록으로 돌아옵니다. 예를 들어 5장을 찍으면 갤러리에서 다시 고르지 않고 5장을 한 번에 전송할 수 있습니다. 갤러리에서 선택한 사진과 촬영 사진을 같은 목록에 섞을 수도 있습니다. 뒤로 가도 이미 저장한 촬영 사진은 목록에 남습니다.

후면 카메라와 기기에서 지원하는 최대 해상도를 기본으로 사용하며, 해상도(높음/아주 높음/최대), 줌, 밝기, 화면 터치 초점을 조절할 수 있습니다. 모니터 반사를 줄이도록 플래시는 끕니다. 제조사 기본 카메라의 프로 모드 등 전용 기능 전체를 복제한 것은 아닙니다. 처음 사용할 때 카메라 권한을 요청하고, Android 9 이하에서는 사진 저장 권한도 요청합니다.

촬영 직후 원본을 `Pictures/PhotoUploader`에 날짜·시간·순번 이름으로 저장하고 그 원본 URI를 목록에 연결합니다. 사진 저장에 실패하면 같은 사진의 저장을 재시도하며, 저장 중에는 카메라 해제를 기다립니다. 앱이 백그라운드로 가면 카메라를 해제하고 돌아오면 다시 초기화합니다. 사진 저장 체크포인트는 재시작 시 복구합니다. 주변 시간대의 다른 사진을 검색해 추가하거나 삭제하지 않습니다.

## 전송 전에 휴대폰에서 자르기·압축

앱의 **전송 전 모니터 자르기·압축**이 켜져 있으면 **휴대폰에서** 큰 중앙 사각형 테두리를 찾아 모니터 밖을 자르고 원근을 보정합니다. 전송용 이미지는 긴 변 최대 2560px, JPEG 화질 90으로 만듭니다. 테두리를 찾지 못하면 전체 사진을 크기 조절·압축하고, 이미 작은 이미지라 가공본이 더 크면 더 작은 원본을 사용합니다. 지원되지 않는 형식은 원본을 사용합니다. 기본값은 켜짐이며, 체크를 끄면 원본 그대로 전송합니다.

목록의 썸네일과 확대 보기는 **실제로 전송할 파일**입니다. 예상 전송 용량과 원본 대비 감소율도 표시합니다. 자동 검출은 화면 안의 큰 창을 모니터로 오인할 수 있으므로, 자르기가 맞지 않으면 체크를 끄고 원본 미리보기로 돌아갈 수 있습니다. 사진마다 원본과 가공본을 동시에 보내지 않고 **한 개만 전송**합니다. 네트워크 요청의 작은 multipart 헤더 용량은 예상 이미지 용량에 포함하지 않습니다.

휴대폰 원본은 가공 중에 수정하거나 삭제하지 않습니다. PC 저장 성공 후 기존 삭제 옵션에 따라 실제 원본을 삭제합니다. 새 앱은 PC 추가 자르기를 요청하지 않으므로, PC에는 전달받은 파일 한 개만 저장되며 `_originals/`에 원본을 추가로 보내지 않습니다. PC에서 자르던 이전 버전의 요청은 서버에서 계속 지원합니다. 전송 준비에 실패하면 업로드·원본 삭제를 시작하지 않고 재시도할 수 있습니다.

## 원본 삭제

삭제 체크박스 기본값은 true입니다. Android 시스템 파일 선택기의 **이미지** 또는 **사진**에서 여러 사진을 선택하세요. 원본 URI를 보존하기 위해 Android에서는 `image_picker.pickMultiImage()` 대신 네이티브 `ACTION_OPEN_DOCUMENT`를 사용합니다. 업로드용 복사본의 경로와 원본 파일명을 별도로 보관하며 전송 시 원본 파일명을 사용합니다.

PC가 모든 파일을 저장하고 HTTP 200을 반환한 뒤에만 원본 삭제를 요청합니다. Android 11 이상에서 Android가 원본 MediaStore URI를 제공하는 사진은 `MediaStore.createDeleteRequest()`의 시스템 확인 창에서 승인하면 실제 원본을 영구 삭제합니다. Android 10 이하에서 이 앱이 촬영한 사진은 해당 MediaStore 원본을 삭제하며, 갤러리 문서 제공자는 `DocumentsContract.deleteDocument()`를 사용하고 필요한 시스템 승인을 처리합니다. 삭제 완료 뒤 업로드용 복사본과 선택 목록을 정리하고 완료 메시지를 표시합니다. 앱은 열린 상태로 유지되어 다음 사진을 선택하고 전송할 수 있습니다. 삭제 체크를 해제한 경우에도 전송 완료 후 선택 목록을 비웁니다. 파일명이나 용량으로 원본을 추측하지 않습니다.

삭제 체크가 켜져 있으면 촬영한 사진도 PC 전송 성공 후 실제 원본을 삭제합니다. 삭제 체크를 끄면 촬영 원본은 `Pictures/PhotoUploader`에 유지되고 업로드용 복사본과 선택 목록만 비웁니다. 삭제 취소 또는 실패 시 목록을 유지하고 오류를 표시합니다. **전송 완료 처리 계속**을 누르면 재전송 없이 남은 처리를 재시도합니다. 선택한 원본 URI와 전송 완료 상태, 개별 삭제 완료 상태를 로컬에 저장하므로 앱이 재시작되어도 이어서 처리합니다. 삭제를 지원하지 않는 제공자는 성공으로 처리하지 않습니다. 기기의 로컬 사진을 선택하세요. 클라우드 동기화 서비스의 원본/백업 보존 정책은 해당 서비스의 설정을 따릅니다.
